# MailBeacon

简约风格的 macOS 邮件客户端，主打「新邮件到服务器后立刻出现」：每个邮箱保持一条常驻 IMAP IDLE 连接，由服务器主动推送。

最新版本见 [Releases](https://github.com/lsclpangpang/mailbeacon/releases/latest)，各版本的变化见 [CHANGELOG.md](CHANGELOG.md)。

- **收信**：多账号、所有收件箱合并视图、IDLE 实时推送（服务器不及时推送时约 30 秒检查一次新邮件；不支持 IDLE 的服务器自动改为 15 秒轮询）、列表顶部的「收取」按钮（`⇧⌘N`）立即检查新邮件并提示收到几封、列表显示正文摘要、Dock 未读数
- **视图**：所有未读、已加星标、所有草稿、所有已发送等跨账号聚合视图；列表可按未读、红旗、附件、@我 筛选；「按会话显示」把来回的邮件合成一行，阅读时列出整个会话（包括已发送里自己的回复）
- **通知与后台**：新邮件系统通知，可选显示内容（发件人和主题 / 只显示发件人 / 只提示有新邮件）、免打扰时段、按账号静音，以及收件箱之外也要提醒的文件夹；托盘（菜单栏）图标、开机自动启动，关闭窗口后继续在后台收信
- **读信**：HTML 邮件放进沙盒显示，默认拦截远程图片（可「显示图片」或「始终显示此发件人的图片」）、内嵌图片、附件保存到「下载」；也可下载完整 `.eml` 邮件，保留原始邮件头、正文和附件。正文里的网址、邮箱（`mailto:`）和电话（`tel:`）链接用系统默认程序打开，纯文本邮件中以 `http://`、`https://`、`mailto:`、`tel:` 开头的地址也会自动变成链接；邮件内的锚点链接只在正文里跳转，其他类型的链接一律拦截
- **自动保存**：按邮箱设置本地目录，自动下载启用后新到收件箱的完整 `.eml` 邮件；保存进度跨重启保留，断线或重开应用后补下载，不改变邮件的已读状态
- **写信**：新邮件、回复、全部回复、转发；富文本编辑（字体、字号、颜色、加粗、列表、对齐、链接、图片、表格）；选择或拖入附件；自动保存草稿（存到服务器草稿箱，离线或 POP3 时存本地草稿）；邮件模板；定时发送；请求已读回执。回复内容与原邮件引用分开编辑，保留原邮件的 HTML 排版、表格、链接和内嵌图片（普通附件不会自动随回复或转发带出）。每个账号可设置独立签名，写信时自动加入并可编辑。发出后会确认「已发送」里有这封邮件，没有就补存一份，有就不重复保存
- **整理**：星标、标为未读、删除（在废纸篓里再删就是彻底删除）、归档（Gmail 归档到「所有邮件」）、垃圾邮件、新建服务器文件夹（支持中文）、移动到任意文件夹或新建后立即移动、搜索全部历史邮件（本地索引，未加载的旧邮件也能搜到）、只看未读；收信规则按发件人、收件人、主题或附件自动移动、标为已读或加星标
- **通讯录**：联系人与分组，写信时联想收件人（含最近联系人），支持 vCard 和 CSV（含网易等导出的 GBK 编码）导入导出
- **账号**：腾讯企业邮、QQ、163、126、Gmail 自动填服务器；其他邮箱手动填写。授权码存在系统钥匙串，不落盘

## 安装测试版

1. 打开 [Releases](https://github.com/lsclpangpang/mailbeacon/releases/latest) 下载最新的 `MailBeacon_*_universal.dmg`（通用版，Apple Silicon 和 Intel 都能用）。每次合并进 `main` 会自动打包发布；也可以在 Actions 的「发布 macOS」或「检查」里下载 `MailBeacon-macOS` 产物
2. 打开 dmg，把 MailBeacon 拖进「应用程序」
3. 没有 Apple 开发者证书签名，第一次打开会被拦截。在终端执行一次：
   ```sh
   xattr -dr com.apple.quarantine /Applications/MailBeacon.app
   ```
   或者先双击打开一次，再到「系统设置 → 隐私与安全性」里点「仍要打开」
4. 添加邮箱时填写**授权码**，不是网页登录密码（各家的获取方式在添加页面有提示）
5. 第一次读取授权码时 macOS 会询问是否允许访问钥匙串，选「始终允许」

快捷键：`J`/`K` 或 `↓`/`↑` 上下封（会话模式下按会话移动），`R` 回复，`A` 全部回复，`F` 转发，`E` 归档，`S` 星标，`U` 标为未读，`⌫` 删除，`/` 或 `⌘F` 搜索，`⌘N` 写邮件，`⇧⌘N` 收取新邮件，`⌘↩` 发送，`Esc` 关闭。

「设置」中的每个邮箱账户可点击账户标题展开或收起，各账户独立控制；收起不会清空尚未保存的输入，账户标题仍显示进行中的全量下载进度。签名按账号填写并点击「保存签名」，清空后保存即可关闭。新邮件、回复和转发都会带入签名；切换发件账号会替换尚未修改的自动签名，已经手动修改的内容会保留。

### 写信、草稿与模板

写信窗口上方是格式工具栏，最后一个按钮是「模板」：可以把当前邮件（主题和正文，不含签名）存成模板，之后一键插入；主题为空时会一并填上。附件可以点「附件」选择，也可以直接把文件拖进窗口，总大小上限 50 MB。写信过程中会自动保存草稿，优先存到服务器的草稿箱；POP3 账号或离线时存为「本地草稿」，在侧栏单独显示。

「定时」可以选择「今天 18:00」「明天 08:00」等常用时间，或者指定日期和时间。邮件立即组好，存进「定时发送」（有待发邮件时侧栏才显示），到点由后台发出并补存到「已发送」。在「定时发送」里可以立即发送、修改时间，或取消定时（邮件转回草稿）。到时间时 MailBeacon 需要在运行（可以只在后台）；关闭期间到点的邮件，下次打开时发出。断网时每小时自动重试，被服务器拒收的会在多次失败后停下，等你处理。

勾选「已读回执」会请收件人读到邮件后回一封回执，对方可以拒绝。收到请求回执的邮件时，阅读区会询问是否发送，**从不自动发送**；回过或拒绝过的邮件会在服务器上标记 `$MDNSent`，其他客户端也不会再问。回执地址和发件人不一致时会提示（常见于邮件追踪）。

### 通讯录

侧栏「通讯录」可以新建联系人和分组、导入导出 vCard（`.vcf`）或 CSV。写信时在收件人栏输入名字或地址会联想联系人、分组和最近联系人；选中分组会填入全部成员。最近联系人可以在联想列表里用 × 或 Shift+Delete 去掉。

### 收信规则

侧栏「收信规则」里按顺序列出规则，可以启用或停用、调整顺序、编辑和删除；在邮件上右键选「按此发件人新建规则…」可以快速建立。每条规则属于一个 IMAP 账号，条件可以是发件人、收件人（含抄送）、主题包含 / 不包含 / 等于，或有 / 没有附件，可选择全部满足或满足任意一个；动作是移到文件夹、标为已读、加星标。收件箱来了新邮件时按顺序执行，命中的都会执行，移动以第一条为准；规则移走的邮件如果用户又移回收件箱，不会再被移走。规则在 MailBeacon 运行时生效，关闭期间到达的邮件可以用「对收件箱最近 500 封执行」补上。被规则移走的邮件不会被「自动下载新邮件」保存；移到设置里勾选了提醒的文件夹时，会从那个文件夹发出通知。

### 会话模式

列表右上角「更多」里的「按会话显示」会记住你的选择。打开会话时，阅读区上方列出同一会话的所有邮件（按时间排列，来自其他文件夹的会标出，例如「已发送」），点击即可切换；同时会把列表里这个会话的未读邮件标为已读。会话按邮件的 Message-ID、In-Reply-To、References 组合，没有这些信息的回复按主题归到最近的同主题邮件。

### 通知与托盘

「设置 → 通知与常规」可以关闭通知、选择通知内容、设置免打扰时段（结束早于开始表示跨过午夜），以及显示托盘图标、开机自动启动（启动后在后台运行）。每个邮箱的设置里可以单独关闭该账号的提醒，并勾选收件箱之外也要提醒的文件夹。窗口在前台时不弹通知；一次超过 3 封时，前两封单独提醒，其余合成一条。有托盘图标（或在 macOS 上）时关闭窗口只是隐藏，App 继续收信；再次打开 App 只会把已有窗口叫出来。

### 回复与引用

回复时在上方输入新内容，下方显示保留格式的原邮件。远程图片仍按图片显示设置处理；原邮件为 HTML 时，发信同时带有 HTML 和纯文本版本，内嵌图片从原邮件中保留。尚未编辑时，取消、右上角 × 或 Esc 可直接关闭；修改后会显示「继续编辑 / 放弃修改」。发送过程中会暂时锁定窗口，避免重复发送或丢失正在发送的内容。

在列表里右键点击邮件，即可「下载邮件（.eml）」或「移动到…」，无需先打开邮件，也不会因此标为已读。键盘聚焦邮件后可按 Shift+F10 打开同一菜单。下载会保存到系统「下载」目录并在访达中显示，文件名采用邮件主题，同名文件不会覆盖；阅读区右上角「更多」也有下载和移动入口。侧栏「文件夹」旁的加号可新建文件夹；「移动到…」可选择已有文件夹，也可选择「新建文件夹并移动…」。

在「设置」中找到要保存的邮箱，启用「自动下载新邮件」，选择本地文件夹后保存设置。每个邮箱独立配置，默认关闭；只下载生效后新到收件箱的邮件，不会批量下载历史邮件。自动保存的 `.eml` 包含邮件头、正文和附件，已有文件不会被覆盖，也不会逐封弹出访达。

每个邮箱可选择一种关键词过滤模式：「不过滤」保存全部新邮件；「白名单」仅保存命中关键词的邮件；「黑名单」跳过命中关键词的邮件。黑白名单互斥，关键词每行一个，任意关键词出现在邮件主题、发件人名称或地址、正文中即算命中，不区分大小写，不匹配附件或 HTML 代码。最多 100 个关键词，每个最多 200 个字符；开启黑白名单时至少填写一个。切回「不过滤」会保留关键词，方便再次启用。手动下载单封邮件不受这些规则限制。

自动下载需要 MailBeacon 运行；关闭应用时暂停，重新打开后会补下载关闭期间收到的新邮件。保存失败会在该邮箱的设置中显示原因并重试；命中规则成功保存或按规则跳过后记录进度，重启后不会反复处理。关闭自动下载不会删除已经保存的本地邮件。重新启用、更换保存目录或更改有效过滤规则时，会从当时的新邮件重新开始，不追溯旧邮件；保存未更改的设置会保留原下载进度。已有账户默认「不过滤」，升级后保持原下载行为。

要备份历史邮件，在「设置」中找到对应账号，在「下载此账号全部邮件」中选择本地文件夹并开始。该操作读取服务器上所有可访问的邮件文件夹，包括收件箱、已发送、草稿、自建文件夹、垃圾邮件和已删除；完整 `.eml` 原文含附件，按账号和邮件文件夹分别保存，不改变已读状态。邮件若同时出现在多个服务器文件夹中，会分别保留各文件夹的副本。

单封、自动和全量下载均以邮件主题命名，例如 `会议纪要.eml`；同名时使用 `会议纪要 (2).eml` 等安全编号，空主题回退为 `邮件-UID.eml`。文件名保留中文等 Unicode 文字，路径特殊字符会净化，过长主题会截短；这些处理只影响文件名，邮件原文字节和附件保持不变。

「继承该账号的黑白名单规则」默认不勾选，下载所有邮件；勾选后使用该账号已保存的过滤模式和关键词，黑名单跳过命中邮件，白名单只保存命中邮件。即使自动下载关闭，也可继承已保存的规则；如果该账号选择「不过滤」，仍保存全部邮件。修改规则后需先点击上方「保存设置」，再开始下载。每次任务使用开始时的规则，中途修改设置不影响当前任务；此选项不会更改自动下载设置或进度。已保存到本地的邮件不会因为更改规则而被删除。

全量下载先统计所有文件夹中实际存在的邮件，统计时显示已扫描文件夹数；统计完成后显示「已处理 / 总计」、百分比和进度条。总计是本次扫描固定的服务器邮件数（过滤前），同一邮件在不同文件夹的副本分别计数。已处理包含已保存、已存在、按规则跳过、单封处理失败及扫描后从服务器移除的邮件，明细分别显示；处理到 100% 不代表没有失败，应同时查看任务结果。文件夹扫描失败时不展示不完整的总数或百分比，统计中也可取消。

下载在后台运行，关闭设置或收起账户不会停止任务，退出应用会中断；再次选择同一父目录会重新扫描核对已有文件，保留已下载内容且不重复生成文件。已有文件内容不一致、邮件无法解码以检查规则或部分文件夹下载失败时会明确报错，不会覆盖文件或显示全部完成。下载范围以本次扫描的邮件边界为准，之后新到的邮件可由已启用的自动下载按其规则处理，或下次全量下载时补齐。

旧版保存的标识式文件名，会在同一目录再次下载到同一邮件、核对完整原文一致后迁移为主题名称；同名的其他文件会保留，通过编号避让。原有关联文件内容不一致时会保留文件并报错，不会覆盖。升级不会在后台批量改名，自动下载也不会追溯已经处理过的旧邮件。归档目录中的隐藏索引用于识别和核验已有邮件，请与邮件文件一并保留。

## 开发

```
src-tauri/   Rust 后端：IMAP 同步（sync.rs）、读信/文件夹（imap.rs）、发信与已读回执（smtp.rs）、账号（config.rs）、
             草稿（drafts.rs）、通讯录与本地数据库（contacts.rs）、通知偏好（prefs.rs）、收信规则（rules.rs）、
             会话（threads.rs）、模板（templates.rs）、定时发送（outbox.rs）
ui/          界面：原生 HTML/CSS/JS，不需要打包工具；mock.js 是浏览器预览用的假数据
cli/         最早的收信速度原型（命令行），见下文
```

```sh
npm ci                     # 安装 Tauri CLI
npx tauri dev              # 本地运行（Mac 上）
npx tauri build --target universal-apple-darwin --bundles dmg
```

只看界面不需要编译：用浏览器直接打开 `ui/index.html`，会自动加载 `mock.js` 里的假数据。地址后加 `?open` 打开第一封邮件，`?compose` 打开写信，`?empty` 显示首次使用的欢迎页。

### 测试

```sh
cargo test -p mailpulse-app        # 单元测试（含内存 IMAP 测试服务器上的协议测试）
npm test                          # 界面逻辑回归（签名、邮件操作、下载设置、规则、会话、通知设置等）
npm run test:e2e                  # 在无头 Chrome 里用 mock.js 走真实界面：富文本写信、收信规则、通知设置、会话、模板、定时发送、已读回执
```

`npm run test:e2e` 需要本机装有 `google-chrome`，不连接邮箱。

GitHub Actions：每次推送（`main` 以外）和发往 `main` 的 PR 会运行「检查」工作流（版本与更新记录、格式、构建检查、前后端单元测试），PR 还会运行「PR 标题」检查；合并进 `main` 后「发布 macOS」会按 PR 标题决定是否发新版本，需要发版时自动测试、打包通用 dmg 并创建 `v<版本>` 的 Release。

### 发版

版本号由 PR 标题自动决定，不用手动改：

| PR 标题 | 含义 | 合并后的版本 |
| --- | --- | --- |
| `fix: 修复……` | 修复 | 升末位，0.2.0 → 0.2.1 |
| `feat: 新增……` | 新功能 | 升中间位，0.2.0 → 0.3.0 |
| `feat!: ……`（任何类型后加 `!`） | 重大变更 | 升首位，0.2.0 → 1.0.0 |
| `docs:` `test:` `ci:` `build:` `chore:` `refactor:` `style:` | 文档、测试、维护 | 不发新版本 |

- 类型后可以加范围，如 `fix(search): 中文搜索`；冒号用英文 `: `（带空格）或中文 `：`。标题不合规时「PR 标题」检查失败，改好标题会自动重跑
- 新版本号以最新的 `v*` tag 为基准，看这之后合并的**所有** PR，取其中升得最多的那种（例如一个 `fix` 加一个 `feat` → 升中间位），每个 PR 在更新记录里写一条。排队时被合并掉的发布、提交了版本号但打包失败的发布，下次都会一起补上
- GitHub 自动生成的撤销 PR（`Revert "fix: ……"`）按修复处理；只改了 `.md` 文件的合并不触发「发布 macOS」，其中的 PR 会算进下一次发布
- 「PR 标题」检查目前只是提示（`main` 没有开分支保护），标题不合规的 PR 合并后不会发版。以后开分支保护时可以把它设为必需检查
- 「发布 macOS」改好 `tauri.conf.json`、`Cargo.toml`、`Cargo.lock`、`package.json`、`package-lock.json` 的版本号和 `CHANGELOG.md`，以 `chore(release): v<版本>` 提交回 `main`，tag 打在这个提交上
- 发布说明默认是每个 PR 标题冒号后面的内容加 PR 编号。想写更详细的说明，在 PR 里给 `CHANGELOG.md` 最前面加一节 `## 未发布`，发版时这一节会改成新版本号
- 需要指定版本号时，在 PR 里运行 `npm run release:version -- 1.0.0` 并写好 `CHANGELOG.md` 的这一节；比所有 tag 都新的版本号会按原样发布
- 手动运行「发布 macOS」会按当前版本重新打包，覆盖已有 release 的安装包
- 发版后只修改 `CHANGELOG.md`（例如改错字）时，「更新发布说明」工作流会刷新已有 release 的说明，不重新打包
- 本地预览：`npm run release:check` 检查各处版本一致，`npm run release:notes -- v0.2.0` 预览发布说明，`node scripts/release.js title "fix: ……"` 检查标题

`CHANGELOG.md` 的格式：第一行是 `# 标题`，接一个空行；每个版本一节，标题写成 `## 0.3.0`（也可以写 `## v0.3.0`）。版本号不一致、缺少这一节或仍是「（待补充）」时，「检查」和「发布 macOS」都会直接失败。

邮件表格布局回归需使用真实浏览器：在项目根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，打开 `http://127.0.0.1:8765/tests/mail-layout.html`。页面直接调用阅读器和回复引用的生产代码，检查宽、窄窗口下的表格宽度、居中、表头换行及图片拦截策略；不连接邮箱。

端到端测试连真实的邮件服务器跑完整流程（登录、IDLE 推送、收信、HTML/附件解析、标记、移动/删除、发信、补存已发送、回复头），默认跳过。用 Docker 起 GreenMail（IMAP + SMTP）和 Dovecot（IMAP）：

```sh
# 自签 CA + localhost 证书，GreenMail 需要 PKCS12 格式
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_full_flow -- --ignored --nocapture
MAILPULSE_E2E_IMAP=localhost:4993 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_imap_previews -- --ignored --nocapture
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_folder_create_move_export -- --ignored --nocapture
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_auto_download_new_mail_restart_and_retry -- --ignored --nocapture
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_auto_download_keyword_filters -- --ignored --nocapture
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_bulk_download_all_folders_resume_and_cancel -- --ignored --nocapture
# 继承规则测试另需空的 inherit@localhost / pw，避免共享邮箱数据干扰统计
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \

# 下列进度测试还需要 progress@localhost / pw 隔离测试账号
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_bulk_download_progress_snapshot -- --ignored --nocapture
# 下列文件名测试还需要空的 names@localhost / pw 隔离测试账号
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
  cargo test -p mailpulse-app e2e_bulk_download_subject_filenames -- --ignored --nocapture
MAILPULSE_E2E=localhost:3993:3465 MAILPULSE_EXTRA_CA=ca.pem \
```

`MAILPULSE_EXTRA_CA` 指向的证书会被额外信任（IMAP 和 SMTP 都生效），自建邮件服务器也可以用。GreenMail 的部分 FETCH 回包不合 RFC（`BODY[]<0>{n}` 少了空格），摘要只能在 Dovecot 上测；App 里遇到这种服务器会自动停用该账号的摘要，其他功能不受影响。

debug 构建支持 `MAILPULSE_DEBUG_SCRIPT=flow.js`：启动 3 秒后把这段 JS 注入页面，用来在真实 App 里自动走界面流程。发布版不包含这段代码。

解析器安全回归通过子进程和 2 MiB 线程栈验证深层 MIME，覆盖普通邮件附件、base64、quoted-printable、digest、截断输入和内存复制放大。仓库内的 `vendor/mail-parser` 保留了上游许可证和最小补丁说明：限制嵌套层级与嵌套原文复制预算。超过安全上限的邮件会明确报错；需要解析正文的下载过滤不会将此错误当作跳过，也不会推进检查点。原文归档仍保留完整字节。

最近邮件原文的内存缓存同时限制为 30 封和 64 MiB，超大邮件不留在缓存中。看过的 IMAP 邮件原文还会存到数据目录下的 `bodies/`（目录 0700、文件 0600，总量 512 MiB，按最近使用淘汰，单封超过 32 MiB 不存；POP3 不存），重启后再打开不用重新下载；删除账号时一并删除。读取缓存前会重新确认服务器文件夹的 UIDVALIDITY；原邮件身份发生变化时，附件下载和引用内嵌图片会要求重新打开邮件。单封邮件下载采用临时文件写完后原子发布，避免中断留下看似完整的 `.eml`。


## 已处理的情况

- **163/126**：登录后先发 IMAP `ID` 命令，否则会报 "Unsafe Login"
- **服务器不支持 IDLE**：自动降级为轮询
- **服务器保持 IDLE 却不推送**：用不受服务器保活影响的 30 秒硬超时主动检查新邮件；已读、星标和未读数每 5 分钟校准一次，避免放大 IMAP 命令量
- **断线**：立即重连，连续失败才逐步拉长间隔（最长 60 秒）；重连后补收断线期间的邮件，并同步别处做的已读、删除
- **电脑睡眠唤醒**：检测到系统时钟跳变后，所有连接立即重连
- **连接静默失效**：开启 TCP 保活；每次操作超过 20 秒没响应就判定失效；空闲超过一分钟的连接用之前先探活
- **密码错误**：直接停止该账号并提示，不反复重试，避免触发风控
- **SMTP 端口**：587/25/2525 用 STARTTLS，其余（465 等）直接 TLS
- **定时发送不重发**：发送前先记下「正在发送」，中途被关闭时重启后不会自动再发，而是提示先查看「已发送」
- **服务器不支持按邮件头搜索**：会话里只显示已加载的邮件，一小时后再试
- **服务器 IMAP SEARCH 不可靠**：腾讯企业邮 / QQ 会忽略所有文本条件、直接返回整个文件夹（用不存在的关键词也能命中全部邮件），Coremail 虽然支持中文搜索但一次全文搜索要几十秒。因此文本搜索不再发给服务器，改为本地增量索引：启动后后台把每封邮件的摘要（主题、发件人、收件人）和正文开头写进 `local.db` 的 `mail_index` 表，搜索只查本地库，未加载过的旧邮件也能搜到。第一次要按服务器能承受的速度跑一遍（腾讯服务器每封约 0.15 秒摘要、0.7 秒正文，几千封邮件需要十几到几十分钟），期间搜索界面会显示进度并先返回已索引部分；之后每次只补新增邮件
- **大邮件打开慢**（带大量内嵌图片的邮件动辄几百 KB 到几 MB，有的服务器下载速度只有一两百 KB/s）：
  - 读信走每个账号单独的「读信连接」，不排在列表摘要后面；服务器不让多开连接时自动退回命令连接，过一阵再试
  - 超过 256 KB、正文能单独取出的邮件先用 BODYSTRUCTURE 只下载正文文字显示出来，图片和附件随整封原文随后补齐；下载中显示已收到多少
  - 看完一封后预取列表里的下一封（512 KB 以内）；连续翻信时，排队中已经不看的邮件不再下载
- **后台搜索索引中断**：1、5、15 分钟后自动重试，之后每 30 分钟一次，不用等下次搜索
- **Linux 没有托盘支持**（缺少 libayatana-appindicator）：自动按无托盘处理，关闭窗口即退出

## 收信速度原型（cli/）

最早用来验证 IDLE 推送速度的命令行工具：每个邮箱一条常驻连接，新邮件一到就打印出来，并显示「服务器收到 → 本地显示」的延迟，可以和 Apple Mail 对比谁先收到。

```sh
cd cli
cp accounts.example.toml accounts.toml && chmod 600 accounts.toml   # 填授权码
cargo run --release
```

想对比 IDLE 和轮询：同一个邮箱配置两次，其中一个加上 `mode = "poll"`。服务器时间只精确到秒，延迟有大约 1 秒误差。

### macOS 本机签名

没有 Apple Developer 账号时，仓库默认使用 ad-hoc 签名，便于 GitHub Actions 构建。若本机已创建 `MailPulse Local Signing` 证书（旧版本证书名仍兼容），使用下面的脚本构建会自动复用该证书，避免 macOS 每次把应用识别成新的程序并重复询问钥匙串权限：

```bash
./scripts/build-macos.sh --bundles app,dmg
```

本机证书只对创建它的 Mac 有效；其他机器会自动回退到 ad-hoc 签名。
