# MailBeacon 应用标识迁移

应用标识由 `com.lsclpangpang.mailpulse` 改为 `com.lsclpangpang.mailbeacon`。升级后的首次启动会自动运行一次迁移，无需另装工具或重新添加邮箱。

## 使用

1. 从菜单退出旧版 MailBeacon，将新版放回原来的安装位置并替换旧版。
2. 打开新版。首次启动会复制和校验本地数据；缓存较多时需要等待，并预留一份旧数据大小的磁盘空间。
3. 核对账户、草稿和定时邮件；在 macOS 系统设置中确认新版 MailBeacon 已允许通知。系统通知授权不能随文件迁移。

迁移成功后，新版使用以下目录：

- 邮箱数据：`~/Library/Application Support/com.lsclpangpang.mailbeacon/`
- 界面偏好：`~/Library/WebKit/com.lsclpangpang.mailbeacon/`

账户、`local.db`、加密密钥、草稿、待发邮件、邮件缓存及其余配置一起复制。外部下载目录保留原位置；账户设置中指向旧数据目录内部的下载和归档路径会调整为新目录。WebKit 数据整体复制，用于保留账户配色、布局、会话开关、信任图片发件人和回执处理记录。

开机启动仍使用 `MailBeacon.plist`。如果同时移动了 App 的安装位置，请在新版设置中关闭再开启「开机自动启动」，更新启动路径。

## 出错与恢复

迁移在收发信启动前完成。旧版仍在运行、新目录已有未标记的数据、磁盘写入失败、数据库损坏或密码与密钥不匹配时，应用会显示原因并停止启动，不会用空配置继续运行。关闭旧版或排除存储问题后可重新打开重试。新旧目录冲突时，请先备份并人工确认要保留哪一份，不要直接删除目录。

两个旧目录仍保留在各自的 `com.lsclpangpang.mailpulse/` 路径。它们是升级时的副本，之后不会同步新版的修改。**开始迁移后不要再次运行旧版，尤其旧目录内仍有待发定时邮件时，旧版可能重复发送。** 若需要回退，应退出所有版本，先备份新旧目录，再核对并处理旧版的待发任务。

新数据目录中的 `.identity-migration.json` 标记该目录已完整发布；邮箱数据目录内的 `.identity-migration-finished` 标记两个目录都已完成。不要手工添加或复制迁移标记。迁移完成后，新版不会再从旧目录导入数据。中断留下的 `.mailbeacon-migrating-*` 是未启用的暂存目录，重试时只自动回收带本工具标记的副本及空目录，不删除身份不明的目录或链接。

如果只完成了一个目录就中断，重试会比较旧源校验值。旧版后来新增或修改过草稿、待发邮件等数据时会停止，不会启用过期副本。仅在新版从未成功启用、旧目录仍是完整最新数据的情况下，可退出所有版本，把两个新目录分别改名留作备份，再重新打开新版从头迁移。新版已经使用过时，应先核对新旧数据，不能直接这样重置。

备份新版时请退出应用，备份完整邮箱数据目录；只复制 `local.db` 无法恢复加密密码，必须同时保留 `secrets/credentials.key`。如需保留界面偏好，再备份对应的 WebKit 目录。

## 验证边界

自动化测试使用隔离的临时目录，覆盖重复启动、复制中断、真实进程终止后的回收、源数据变化、目录冲突、链接拒绝、缓存时间保留、WAL / rollback journal 恢复及错误密钥。迁移过程不调用旧钥匙串。更早版本尚未转为本地加密的账户，仍沿用既有的一次性钥匙串迁移流程。

旧进程检查在复制前后和每次启动执行，但旧版不认识新版的迁移锁，不能保证用户同时启动两种版本时的互斥。不要并行运行新旧版本。macOS 实际通知权限、WebKit 偏好恢复和真实安装升级需单独验收，单元测试不能替代这些验证。
