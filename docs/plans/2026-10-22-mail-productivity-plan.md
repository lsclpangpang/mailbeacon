## 1. 目标与范围

本次设计覆盖六项：发送缓冲与撤销；稍后处理和未回复提醒；保存搜索/智能文件夹；附件中心和快速预览；快速回复/折叠写信窗口；贯穿这些操作的轻量动画。

既有模板、定时发送、发送记录、移动撤销、离线阅读、原生菜单、通知跳转、多选拖选继续复用。命令面板、AI 自动整理、日历、团队协作、附件全文/OCR、通用离线写队列不纳入这一轮。

以下默认值属于本方案建议，可在实施前调整：发送缓冲默认 10 秒，选项关闭/5/10/20/30 秒；提醒在本机运行；同一时刻一个可编辑写信会话，允许折叠；首版快速预览覆盖 PDF 和常见图片。

## 2. 已有基础与必须先处理的边界

| 现状 | 对本次方案的影响 |
| --- | --- |
| `sending.rs` 普通发送直接进入 SMTP；`send_records.rs` 已持久记录 Prepared/Submitting/Accepted/Rejected/Unknown | 新增的取消窗口必须发生在 SMTP 提交之前，继续复用现有结果与副本补存规则 |
| `outbox_worker` 每 15 秒检查一次，取消操作会取得全局发送锁 | 不能直接用现有轮询或跨网络持有的全局锁实现 10 秒撤销，需要按消息仲裁、按截止时间唤醒 |
| 邮件引用包含账户、接收代际、文件夹、UIDVALIDITY、UID | 稍后任务、附件索引和搜索结果不能只保存 UID 或 Message-ID |
| `requestServerSearch` 遇到空关键词会清空结果 | 智能文件夹与附件中心需要“无关键词、只有条件”查询，先统一查询模型 |
| 搜索已有覆盖程度、修订号和分页游标；POP3 能力受限 | 新入口沿用覆盖说明与协议边界，不承诺完整服务器搜索 |
| 写信自动保存与附件生命周期挂在 compose DOM；`closeOverlay` 会释放资源 | 折叠不能走关闭路径，先把编辑会话与弹层生命周期分离 |
| 列表 66px 固定行高，超过 120 项虚拟化；拖选依赖固定几何 | 拖选时禁止行高和位置动画，布局动画不能破坏点击、焦点、虚拟索引与滚动锚点 |
| 已有正文、HUD、菜单入场动画和部分减少动态效果支持 | 本轮补齐一致性和结果反馈，避免叠加重复动画 |

## 3. 共用约定

### 3.1 身份、持久化与异步结果

- IMAP `MessageRef` 始终使用 `(accountId, receiveEpoch, folder, uidValidity, uid)`。本地草稿、发送记录使用各自持久 ID；POP3 不用进程内序号冒充跨启动引用。
- 移动后的可靠身份映射可更新关联；无法可靠定位时标记“原邮件位置待确认”，不按主题或相同 UID 猜另一封。
- 账户删除取消该账户尚未提交的发送/提醒并清理应用拥有的索引；导出文件不删除。账户接收端点变化隔离旧引用。智能文件夹引用失效时显示修复入口，不能静默扩大到全部账户。
- SQLite 新表使用独立迁移登记，避免覆盖既有通讯录 `user_version`。迁移可重复执行，失败回滚；旧数据默认保持原行为。迁移、身份检查与崩溃恢复完成之前，不启动新增后台任务。
- 请求带对象 ID、版本/查询修订号。旧回调不得覆盖新选择、关闭后的预览、切换后的账户或更新后的草稿。
- UI 只反映确认状态；倒计时、成功动画、结果数量均以后台事实为准。时间显示使用用户本地时区，持久截止时间保存 UTC；相对查询记录相对规则，不在保存时冻结成某一天。

### 3.2 键盘和焦点

- 先确定最上层可交互作用域（模态窗口/预览、其上的菜单、编辑器或主内容），再在该作用域内判断输入法、文本输入和具体快捷键；事件不能穿透到背后的作用域。多选/普通阅读仅在列表或阅读区拥有焦点时接收操作。
- Space 在附件项目获得焦点时预览附件；预览内按 Space 不前进邮件；普通阅读仍按现有规则滚屏/下一封。编辑正文时所有字符交给编辑器。
- Esc 只关闭最上层预览/菜单；编辑中按现有草稿保护处理；退出后焦点返回触发按钮/原附件/原列表行。
- 鼠标点击、键盘、原生菜单共用动作状态，不出现某个入口能绕过取消窗口或重复发送的问题。发送快捷键及原生发送菜单只对可见、可编辑且拥有焦点的写信作用域生效；折叠会话即使保留 DOM 也不得响应，搜索、设置或预览内的 ⌘Enter 不能发送后台草稿。

## 4. 功能方案

### A. 发送缓冲与撤销

**路径**：写信 → 点击发送 → 持久保存可恢复发送任务 → 写信窗口收起，显示“10 秒后发送 · 撤销 · 立即发送” → 到期提交 → 发送记录展示结果。

1. 发信设置可选择缓冲时间，默认 10 秒。普通发送、快速回复和快捷键发送一致。明确选择“定时发送”的邮件沿用定时任务，到点不再额外缓冲一次；“立即发送”也不再套第二层缓冲。
2. 保存失败时保留编辑器，不启动倒计时、不清理附件、不调用 SMTP。任务保存成功后才能关闭编辑器。缓冲队列在“发送记录”中持续可见，不依赖几秒 toast。
3. 撤销成功会取消提交并恢复同一个草稿，可继续编辑；保留收件人、抄送、密送、正文、引用、内嵌图片、附件和跟进选项。若已有另一个编辑会话，恢复为可见本地草稿入口，不能覆盖用户正在写的内容。
4. 到期提交与撤销竞争时由后台对同一任务做原子状态转换；只有其中一个成功。撤销赢了则 SMTP 调用为零；提交赢了则显示“已开始发送，无法撤销”，不提示已撤销。
5. 发送中不能再撤销。Accepted 才显示“已发送”；副本补存失败独立展示，绝不因此重发。Unknown 显示“发送结果待确认”，不自动重试。
6. 离线、认证失败或确定未提交的失败显示“等待处理/发送失败”，保留原文，用户选择重试；普通缓冲发送不无限后台重试。
7. 正常后台运行到期发送。退出/崩溃时尚在缓冲的任务，重启进入“已暂停，请确认发送”，不突然补发；已进入 Submitting 的任务沿用 Unknown 恢复。既有定时发送的到期补发行为不变，界面明确区分两类。
8. 队列固定发件地址和 SMTP 端点指纹。发件地址或 SMTP 主机/端口改变时暂停核对；仅更新授权码可使用最新凭据重试。提交在账户配置门内校验，不能向用户后来换入的服务器悄悄提交。

**唯一发送状态与事务边界**：

- `persisting` 仅为前端等待状态。扩展现有 `send_records` 为唯一执行状态来源，新增 Buffered/Paused/Cancelled；缓冲元数据表只存截止时间、草稿等，不另存可独立变更的发送状态。Prepared 仅保留给既有立即/定时发送的准备阶段，缓冲任务不能同时存在一个可重发的 Prepared 影子记录。
- 原文、可编辑草稿及受管理附件先完整写入并确认持久化，再以同一个 SQLite 事务发布发送记录和缓冲元数据。事务失败不产生可领取任务；崩溃留下的孤立文件只做恢复/清理，不推断为待发送。enqueue 按 accountId + requestId 幂等，并校验 composeSessionId/revision 与 payloadHash；同键不同内容报冲突。
- cancel/到期 claim/立即发送共用发送记录的版本条件更新：Buffered 可取消或领取，Paused 只能通过用户显式恢复/确认入口处理；领取原子转换为 Submitting，并发操作只有一方获胜。取消状态与草稿恢复意图在同事务提交，恢复器按 sendRecordId 幂等恢复草稿。
- 所有入口，包括现有 `resend_record`、`begin`、定时任务、完整写信与快速回复，均经过同一状态裁决。旧重发接口不能直接提交 Buffered/Paused/Cancelled；Accepted 不能重发，Unknown 沿用既有明确确认保护。执行器只接受原子领取得到的记录版本/令牌，不靠另一张表或前端状态放行。
- 固定顺序为账户配置读门 → 发件身份核验 → 短数据库事务领取 → SMTP；配置门保证已核验端点在该次提交期间不被替换，数据库事务不跨网络持有。撤销只取得短数据库锁，不等待 SMTP 锁或另一封发送。
- 状态为 Buffered → Submitting → Accepted/Rejected/Unknown；Buffered → Cancelled/Paused。重启时 Buffered → Paused、Submitting → Unknown；Paused 的用户确认仍经同一领取裁决。没有确认接受的任务不得自动转成成功。

**工程落点**：新增缓冲队列模块与后台按时唤醒器，复用 `sending.rs`、`send_records.rs` 的原文准备及结果处理；前端独立发送状态模型。不能仅延迟前端调用，也不能把短暂的附件 token 作为持久任务的唯一来源。原文、含密送的可编辑草稿和附件归队列所有，取消并恢复或确认完成前不释放。

### B. 稍后处理＋未回复提醒

**入口**：阅读区与右键菜单增加“稍后处理”；快捷选项“今晚、明早 9 点、下周一、自定义”。侧栏提供“稍后处理”和“待跟进”视图。写信时可选择“若未检测到回复，提醒我”。

**稍后处理首版采用本地视图规则**：

- 仅在各账户收件箱及聚合收件箱隐藏，包括这些收件箱内的未读/星标等筛选。独立的“所有未读”`__unread`、“红旗”`__starred`、其他实体文件夹、搜索和智能文件夹仍包含它，并显示提醒时间；“稍后处理”入口始终可找到。不执行 IMAP MOVE、不改变已读，也不改变网页邮箱位置。原服务器未读数保持，收件箱标明“未读（含稍后）”；列表条数按实际可见结果计算，不用不完整索引推算精确排除数量。
- 到期解除隐藏，并在“待跟进”中出现；首次到期可显示轻提醒和系统通知。正在拖选时先更新后台状态与提示，按 F 的列表快照规则延后整合可见行，不抢焦点。暂存状态、时间、完成/提前恢复操作均跨重启保存。
- 手动打开邮件不自动取消提醒；可以“提前恢复”“改时间”“取消”。原邮件已删除或代际失效时显示状态，不让提醒绑定到另一封邮件。
- 会话模式下明确本次暂存的是当前已解析会话。新回复关联到该会话后提前恢复并提示“有新回复”；收到无法可靠关联的新信时正常显示，不按相同主题一起藏起。
- 到期离线仍显示本地提醒，已有原文可读；没有正文则说明需要联网。应用退出期间不会有本应用通知，重新打开后汇总逾期提醒，不逐条轰炸。

**未回复提醒**：

- 跟进意图（是否启用、间隔）随发送任务预先持久化。收到 SMTP 确认后，在同一个 SQLite 事务写入 Accepted、不可变的 `acceptedAt` 并激活唯一 `sendRecordId` 对应的提醒，不能依赖前端成功回调。事务全成或全败；失败保留 Unknown 语义，不自动重发。启动时按已持久 Accepted 与意图幂等对账，兼容升级/历史缺项；重复恢复只能补一条，期限不因补存副本的 `updatedAt` 改变。撤销、失败或待确认时不启动有效期限。
- 跟进锚点 `anchorMessageId` 是本次 Accepted 邮件自身的 Message-ID，另存 `threadRootMessageId` 只供会话展示。来信 In-Reply-To 或完整 References token 必须精确包含该锚点；仅引用旧会话根、兄弟分支、ID 子串或相同主题都不解除。自己的后续邮件（含已知别名）、退信、自动回复及已读回执不算对方回复。同一会话两次发送各自有独立跟进。
- 展示“尚未检测到回复 · 同步截至某时”，不声称对方一定没回复。当前 `threads::collect` 的截断会话结果不能当作完整回复检测。
- 首版检测范围固定到发送账户的接收端点/receiveEpoch，默认检查该账户所有可选文件夹中的收件箱、归档和自定义目录，排除已发送、草稿、待发、垃圾箱和已删除。界面可查看实际范围和排除项；缺失或无法确认特殊文件夹映射时不擅自宣称完整覆盖。有效回复的正向证据可立即完成提醒，不必等全范围扫描。
- 到期的负向判断需要一次在 dueAt 之后启动并完成的核对轮次：重新列文件夹、冻结本轮集合/目录版本；逐夹记录 receiveEpoch、UIDVALIDITY、已扫描 UID 水位、服务器快照上界、完成时间、错误和分页耗尽状态。首次核对须完整扫描该范围的相关邮件头，后续可基于同代际完整基线做增量；不能仅靠不可信 Date 头或“上次同步过”跳过旧 UID。核对中新增目录或代际改变使本轮失效，补齐/重扫后才判定；显示最早的逐夹完成时间作为保守的“核对截至”。
- 截止时离线、任一范围内目录缺失/失败/未完成分页，或只有旧轮次完整快照，均保持“待核对”；不能用截断会话列表证明没有回复。完整轮次仍未找到时才展示“此范围内尚未检测到回复”。随后持续增量检测，迟到有效回复可完成已到期提醒。用户仍可打开发送记录手动跟进，系统不会自动发追问邮件。
- 对已取得的历史/新邮件头维护轻量关联索引，扫描可取消、有进度，不自动下载完整正文。同一提醒重复唤醒、通知点击与后台到期并发只更新一条持久记录。

**工程落点**：独立提醒表和后台调度，复用完整邮件引用与发送记录 ID；回复检测与用于展示的短会话查询分开。首版持久稍后处理以 IMAP 为保证范围，POP3 入口应明确禁用，不能假装已支持跨重启引用。

### C. 保存搜索／智能文件夹

**路径**：设置搜索范围与条件 → “保存为智能文件夹” → 命名 → 侧栏固定入口。支持重命名、编辑条件、调整顺序和删除视图；删除视图不删除邮件。

- 保存关键词、固定账户/文件夹引用、未读/星标/附件/发件人/日期、垃圾邮件与废纸篓开关、排序。支持没有关键词的条件查询，如“所有有附件的邮件”。
- 保存时明确选择“指定账户”或“全部账户（包含以后添加的账户）”。“当前文件夹”解析成固定账户与文件夹引用，之后切换账户不会悄悄改变保存范围。
- 日期支持固定起止或“最近 N 天”；每次查询按当前本地日期计算相对边界，处理时区和夏令时。
- 复用现有分页和覆盖信息，显示本机索引范围、缺失正文、离线/错误、最后同步时间。空结果与范围失效是不同状态。
- 账户删除、文件夹删除/重命名且无法确认映射时显示“需要修复范围”，保持原条件，不自动扩大或切换同名目录。
- 首版是本客户端视图，不在服务器创建文件夹，不后台同步所有正文。侧栏数量未经完整查询不显示精确总数；可显示“已加载 N 封”，不伪装完整命中数。
- 智能文件夹内沿用普通打开、右键和多选操作；搜索条件切换退出多选。稍后邮件仍按条件命中，并标注稍后时间。
- 临时调整条件显示“未保存的更改”，只有显式保存才修改定义，离开后再进入恢复已保存条件。保存视图清除最后一项条件仍表示其固定范围内的全部邮件，不退回收件箱；普通临时搜索清空词与全部条件则退出搜索。
- 查询是否活动由 SearchSpec/视图状态决定，列表、刷新、加载更多、空状态、J/K/Space 导航一并改造，不能继续用关键词是否为空作为判断。索引变化需要刷新时保留条件与覆盖提示；拖选中新增匹配遵守 F 的统一整合规则。

**工程落点**：抽出可序列化 `SearchSpec`，解耦“正在查询”与“有关键词”；先复用现有 `mail-search.js` 与本地搜索后端，再增加保存视图存储。旧查询游标不能跨条件/索引版本使用。

### D. 附件中心＋快速预览

**入口**：侧栏“附件”。展示文件图标/缩略图、文件名、大小、类型、发件人、所属邮件时间、账户和本地可用状态；可切换 PDF/图片/表格/其他，按文件名、发件人、日期、账户筛选。

- 第一版只保证“已解析过正文的附件元数据”，例如已打开、预缓存或从受信归档原文解析的邮件。明显标注覆盖范围；仅有列表中的“含附件”标志不足以伪造文件名或数量。
- 进入附件中心不下载整个邮箱。可提供“补充附件信息”按用户选择范围、受现有缓存预算限制执行，进度、取消、失败和未覆盖数量可见；不可把后台补充包装成全量完成。
- 每一项定位到完整 `MessageRef + MIME part 标识 + rawHash`，同名附件、同 UID 不同账户、同一邮件多个同名附件都独立；原文改变时重建 part 映射，不按文件名合并删除。CID 内嵌图片默认不列入普通附件，后续可通过“显示内嵌图片”显式查看。
- 点击“预览”或在附件项聚焦时按 Space 打开快速预览；首版 PDF/PNG/JPEG/GIF/WebP 可查看，支持上一份/下一份、下载、默认应用打开、“返回原邮件”。Office、压缩包、HTML/SVG 等显示信息与打开入口，不伪装成已支持内嵌执行。
- 原邮件中的附件也使用同一预览入口。原有双击默认程序打开、右键选择应用和下载操作继续保留。
- 优先复用本地原文/附件缓存，离线可预览已保存内容；未保存、损坏或归档盘离线分别解释。预览不标邮件已读，不发已读回执。只有用户明确返回并打开原邮件才走原阅读路径。
- 预览请求和后端令牌绑定完整来源、partId、期望 rawHash、解析版本；实际读取原文后必须重新校验，摘要不一致则拒绝旧条目并刷新索引，不用旧 part/index 打开新内容。预览完成前切换项目/账户/关闭窗口，旧结果不得闪现到新预览。任务去重与取消按附件身份处理；下载中的临时文件不覆盖用户下载目录。
- 首版预览可用 macOS Quick Look 承担 PDF/图片呈现，前置验证 Tauri 桥接、沙盒文件访问与焦点恢复；如果平台预览不能满足界面/焦点要求，再采用受限图片渲染与可信 PDF 组件。不得直接将任意邮件附件当 HTML 注入当前 WebView。
- 临时预览文件只来自后端解析出的合法附件，路径不直接由网页传入；预览使用期固定持有文件，关闭后按明确策略清理，不能被缓存淘汰中断，也不删除用户已导出文件。

**工程落点**：附件元数据索引增量写入现有正文解析路径；新增带修订号的附件查询 API，复用 `attachment_path`、`archive_source`、离线来源校验和保存路径。缓存淘汰只改变可用状态，不伪称服务器邮件或附件已删除。

### E. 快速回复／折叠写信窗口

**快速回复**：阅读区底部显示“回复 / 回复全部”。点击后在原位输入短回复，默认展示收件人、发件账户、正文、发送与“展开完整编辑器”。展开后继续同一草稿，不重新拼一份邮件。

- 快速回复与完整写信共用 `ComposeSession`、发送缓冲、签名、引用、附件、自动保存和身份检查。回复全部需明确显示收件人，不能隐藏被加入的抄送人。
- 从完整窗口返回快速回复仅在该草稿仍兼容原位布局时允许；附件、复杂格式等不能丢失或被悄悄转纯文本。
- 原位回复 A 时导航到 B，先采集最新输入并保存本地恢复日志，成功后自动折叠为明确标注“回复 A”的草稿条，再切换选择和正文到 B；不能把回复 A 的编辑器摆在 B 底部。失败则保留 A 的选择、正文和输入，提示重试。行点击、J/K/Space、通知、附件返回来源共用该导航门；请求序号保证迟到导航不覆盖更新目标。服务器草稿随后同步。完整模态编辑器仍按自身关闭/折叠规则处理。

**折叠写信**：写信标题栏新增折叠按钮；点击后变成窗口底部“草稿：主题 · 已保存/保存失败”条，可继续浏览或搜索其他邮件，点击草稿条恢复焦点、光标、正文滚动与附件。

- 首版最多一个可编辑写信会话。已有折叠草稿时再次新建/回复，会先恢复现有草稿，并提供“保存并开始另一封”；不能直接覆盖。保存成功后其他草稿仍可从草稿列表打开。
- 折叠只是视图变化，不触发关闭确认，不 dispose 自动保存器，不释放附件 token；会话真正结束后才释放资源。持久恢复使用受管理附件副本，不依赖当前进程 token。
- 最后输入与异步保存以单调修订号仲裁，旧保存结果不能覆盖新输入；保存中切换 inline/expanded/collapsed 不启动第二个保存器。收件人、回执、跟进开关/时间等所有影响发送的字段都参与 revision、dirty 和完整恢复日志，即使只改一个开关也要落盘；切回已保存值按内容比较恢复正确 dirty 状态。图片指纹仅优化比较，不能替代真实草稿数据。
- 真正关闭仍遵循现有保存/放弃保护；发送中禁用修改，缓冲撤销成功再恢复可编辑状态。
- 应用重启后显示“恢复草稿”入口；能恢复到最后一份确认持久保存的修订，不承诺断电瞬间未落盘的按键。持久化使用完整 `buildDraft` 加会话元数据，包含回执请求等发送字段，不能使用会将图片指纹化且遗漏字段的 `composeSnapshot`。服务器草稿副本与本地恢复日志按会话 ID 关联，避免出现两份可编辑副本。
- 引用原邮件的接收代际失效时保留已写正文并说明附件/引用需要重新获取，不按旧 UID 换取另一封信。

**工程落点**：先把 compose 状态与 DOM、`#overlay` 分离成独立会话，再接三种视图。预览、菜单、设置与折叠草稿并存时明确焦点栈和 Escape 路由，不把旧 `closeOverlay` 当作折叠实现。

### F. 动画与视觉反馈

统一目标：让状态变化看得懂，操作能继续。建议时长 120～220ms，仅作为初始调参值；所有完成状态由业务事件驱动，动画不是计时器。

| 场景 | 设计 | 限制 |
| --- | --- | --- |
| 进入/退出多选 | 多选状态、固定几何与命中区域同步切换，再淡入/淡出装饰；立即接受首个拖选事件 | 拖选中不改变行高、位置、命中区域；开始新输入立即结束未完成过渡 |
| 归档/删除 | 已确认成功的行轻淡出，撤销成功时轻高亮恢复 | 部分成功只处理成功项；失败/待确认项保留；虚拟列表首版保持固定行高与原子补位，不做逐行高度收缩 |
| 切信 | 复用并统一现有正文/HUD过渡；连续 J/K 时取消旧动画 | 阅读位置、部分正文更新和焦点不被重置；不累积等待动画 |
| 新邮件 | 顶部显示“有 N 封新邮件”，点击后插入；顶部且空闲时可轻淡入 | 滚动阅读/拖选期间不强行推移列表，不把新邮件加入旧选区 |
| 发送 | 等待发送倒计时、提交中状态、确认成功勾号平滑变化 | 不伪造百分比；Unknown 不播放成功；撤销按钮按真实状态停用 |
| 折叠写信 | 编辑窗口轻收起到草稿条，展开反向恢复 | 会话不重建，附件不释放；保存失败保持可编辑与可见错误 |
| 附件预览 | 使用平台预览转场或短淡入，加载时显示静态占位/真实进度 | 关闭后旧请求不重新打开；大量附件不批量播放动画 |

**可见列表整合规则**：新邮件、稍后到期、新回复提前恢复、智能文件夹新增匹配都先更新持久状态/数量和新增提示。拖选期间固定行身份与几何快照，手势结束后按消息身份和滚动锚点整合，旧选区不纳入新行；非拖选但正在中部阅读时保留当前列表，点击提示后整合，顶部且空闲时可直接更新。后台状态变化不抢焦点，也不通过更改行高做动画。

统一覆盖 `prefers-reduced-motion`，包括现有 scrim/sheet/pulse 等遗漏。减少动态时以即时切换、文字、静态图标表达状态；后台与不可见页面停止装饰性持续动画。触发网络操作不依赖 `animationend`；动画中途取消不取消已提交业务，也不吞键盘输入。

## 5. 建议的数据与接口契约（实施前锁定）

| 对象 | 最小字段/接口 | 约束 |
| --- | --- | --- |
| BufferedSend / SendRecord | sendRecordId、唯一 state/version、不可变 acceptedAt；缓冲扩展存 requestId/payloadHash、composeSessionId/revision、deadline、senderIdentity、SMTP fingerprint、原文/草稿引用、followupIntent；enqueue/cancel/sendNow/get | 扩展表不另存执行状态；所有入口共用领取裁决；取消与恢复意图同事务，不等网络锁 |
| Reminder | id、kind、sourceRef 或唯一 sendRecordId、anchorMessageId、threadRootMessageId、acceptedAt、dueAt、state/version、scope、folderRosterVersion、逐夹水位/完成时间、notifiedAt | kind 区分稍后/未回复；Accepted 与激活同事务；负向核验需要到期后的完整轮次；操作幂等 |
| SavedView | id、name、order、specVersion、SearchSpec | 存条件而不是固定结果/旧游标；范围失效不扩大 |
| AttachmentItem | MessageRef、partId、rawHash、parserVersion、filename、MIME、size、messageDate、availability、indexRevision；preview 请求包含期望 rawHash/parserVersion | 唯一来源与令牌绑定完整消息身份、part 和内容摘要；读取时复核；覆盖与可用性分开 |
| ComposeSession | id、revision、accountId、mode、recipients（含Bcc）、body、requestReceipt、followupIntent、signature/quote、managedAttachments、draftBinding、saveState | 一个逻辑会话、一个保存器；服务器同步和本地恢复日志分层 |
| MotionPolicy | reducedMotion、gestureActive、visible、actionState、currentTransitionId | 只影响表现，不改变业务状态或邮件身份 |

API 的名称最终可随项目命名调整；公开实现前保持上表状态及响应语义稳定。所有写命令返回确认后的对象版本和状态，前端不得靠本地猜测完成。

## 6. 实施顺序与职责

仍建议一个实施 PR，按模块拆提交。当前方案分支只保存文档；生产实现与可执行测试待下一阶段启动。

| 阶段 | 内容与交付 | 依赖 | 主责 / 复核 |
| --- | --- | --- | --- |
| 0 | 锁定身份、状态、迁移、假时钟/假 SMTP/假 IMAP 测试夹具；预览桥接可行性验证 | 无 | 后端与前端联合 / 另一 agent |
| 1A | 发送缓冲、原子撤销、记录恢复；先接现有写信 | 0 | 后端 / 独立后端 review |
| 1B | SearchSpec、纯条件查询、保存智能文件夹 | 0 | 搜索后端 + 前端 / 独立交互 review |
| 1C | ComposeSession 与本地恢复，折叠/快速回复 | 0，接入发送依赖 1A | 前端 + 草稿后端 / 独立数据保留 review |
| 2A | 稍后处理、跟进与回复索引 | 1A 的发送结果；0 的身份和迁移 | 后端 + 前端 / 独立时序 review |
| 2B | 附件索引/查询/预览/资源生命周期 | 1B；0 的预览验证 | 后端 + 前端 / 独立边界 review |
| 3 | 将 F 的动画逐项接入，统一快捷键/焦点/减少动态 | 相应业务状态已稳定；完整验收依赖 1A～2B | 前端 / 独立 UI review |
| 4 | 联合故障回归、迁移/重启、模拟桌面交互验收、文档 | 全部阶段 | 主 agent / 未参与实现的 reviewer |

独立模块可并行开发，但 `ui/app.js`、命令注册、数据库迁移由单一集成人串行合入，避免并发重写公共状态。每阶段先红后绿，review 问题修复后复审，不用后续功能掩盖前置问题。

实施时按职责选用现有技能：后端使用 `backend-development`，前端使用 `frontend-development`，跨模块测试使用 `integration-test`，独立复核使用 `backend-review` / `frontend-review`；本轮方案审查使用 `plan-review`。这些为后续角色分工，不代表本轮已执行所有技能或实现测试。

## 7. 验收与交付边界

- 完整测试矩阵、夹具和具体执行命令见 TDD 文档。单元测试验证状态与时序，真实桌面交互验证焦点、布局、滚动与动画；截图不能替代交互验收。
- 使用独立数据目录和模拟邮箱完成自动/桌面验收，不拿真实邮件执行删除、退订或发送。真实服务商验证需要明确的测试账户与接收目标，再单独记录结果。
- 不以测试通过替代真实 SMTP/IMAP、睡眠唤醒、Quick Look 或升级安装验证；实施 PR 应分别列出已完成和未完成的证据。
- 本地提醒和智能文件夹不跨设备同步；应用完全退出不会发送或触发本应用提醒。附件中心不承诺附件全文搜索；快速回复不自动写作或自动发送。
- 文档评审通过表示方案具备实施条件，不表示功能或测试已交付。
