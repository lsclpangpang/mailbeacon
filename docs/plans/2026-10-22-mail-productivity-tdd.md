# MailBeacon 邮件效率功能：TDD 与验收设计

关联：[产品方案](2026-10-22-mail-productivity-plan.md)。基线：`8c7f355`。

状态：**测试设计，尚未新增或执行下述测试代码**。表中的预期均是实施验收条件，不是当前版本已经通过的结论。

## 1. 先红后绿的执行方法

1. 每个阶段先锁定对外状态/命令契约与夹具，编写一条真正覆盖用户行为的失败用例，运行并保留失败原因；仅语法错误、错误夹具或环境缺包不算有效红灯。
2. 逐项实现到通过，补上同一状态转换的失败/并发/重启边界；重构后保持绿色。测试断言可观察结果、持久状态、SMTP/IMAP 次数和焦点，避免只检查源码是否出现某段字符串。
3. UI harness 不能替代真实输入事件；数据库测试不能只使用内存伪造，涉及迁移和恢复时使用磁盘临时目录并重新打开 Store。
4. 每阶段由未参与该模块实现的子 agent review；问题先写回归测试再修复，复审通过后进入下一依赖阶段。
5. 记录“用例 ID、首次失败原因、最小修复、通过命令、review 结论”。不把计划中的用例数写成已通过测试数。

## 5. 真实交互验收脚本

实现阶段以隔离演示 App 和真实桌面事件逐步执行，保留关键状态截图/短录屏与文字观察。使用可用的 CUA 控制原生 App；不得用直接修改运行态变量代替用户操作。

1. **发送保护**：输入含Bcc/附件/回执的邮件，发送后撤销，完整恢复；连续发送A后编辑B再撤销A；模拟提交边界/离线/Unknown，核对状态和发送次数。
2. **稍后与跟进**：设一分钟后提醒，在别封邮件中编辑；到期不抢焦点；退出重启归集；分别注入精确回复、同主题新邮件、退信与回执。
3. **智能文件夹**：保存“只有附件”的空关键词条件与“某账户最近30天”；重启后核对；切账户/删除来源/断网/延迟查询，检查范围和覆盖文案。
4. **附件**：同名图片/PDF来自不同账户；Space预览、Esc回焦点、双击默认应用、返回原邮件；切换中下载完成和拔除归档盘；不支持类型有可用出口。
5. **编辑会话**：最后输入后立刻折叠，打开附件与设置再恢复，切换底层邮件、重启、模拟保存失败；核对字段和附件，不只看正文。
6. **动画与多选**：1,000封长列表中拖选到边缘并反向，期间来新信；连续J/K和Esc；系统减少动态开/关；窄窗口核对底部草稿条与状态条布局。
7. **真实协议补验**：使用明确指定的测试账户/接收目标，再核对 SMTP 最终投递、有效回复、系统通知与预览。模拟绿色不能替代这一步；本次方案阶段不发送真实邮件。
