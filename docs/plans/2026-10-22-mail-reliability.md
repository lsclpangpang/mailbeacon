# MailBeacon 日常使用可靠性与效率改进计划

日期：2026-10-22。基线：`origin/main` 的 `5a5ae09`（v0.13.0）。

状态：用户已授权实施七项主体功能。使用一个最终 PR，各功能阶段独立提交，并行工作分支汇总到 codex/mail-reliability。完成记录以本文末尾及最终验证为准。

## 1. 本轮已做的小改

- 归档不可用时，HUD 显示 `Space 滚动 / 下一封 · S 星标 · R 回复`；归档可用时仍显示 `E 归档`。
- 归档按钮继续按真实能力启用或禁用，隐藏提示不等于增加归档能力。
- 文件夹晚于正文加载时，只更新归档按钮及 HUD，不重建正文、不重置两秒计时。
- 保持部分正文加载时的回复提示、快捷键、动画和原有归档路径。
- 已先修改现有测试得到失败，再实现修复；测试覆盖隐藏、恢复显示、失去归档目标、计时与正文节点保持。

## 2. 目标与交付顺序

目标：用户能判断操作是否完成，误操作有明确保护，发出的邮件和本地保存的邮件可以找到，大量邮件能高效整理。

| 批次 | 交付 | 依赖与原因 |
|---|---|---|
| 阶段 1 | 准确结果反馈 + 永久删除确认 | 先修已存在的虚假成功；其结果模型供后续撤销、批量操作复用 |
| 阶段 2 | 持久发送记录与已发送副本恢复 | 基于 阶段 1 的状态展示，发送状态单独建模 |
| 阶段 3 | 账户故障原地修复 | 可与 阶段 2 并行设计；先约定接收身份版本，供搜索/离线使用 |
| 阶段 4 | 搜索范围、覆盖程度、完整正文补索引与分页 | 统一带代际的邮件引用；兼容旧数据库和已有缓存 |
| 阶段 5 | 冷启动离线阅读 | 使用 阶段 4 的快照身份及覆盖信息，不跳过服务器身份校验 |
| 阶段 6 | 普通删除、归档、移动的安全撤销 | 依赖 阶段 1 的逐项结果与代际引用；协议层先验证 UID 映射 |
| 阶段 7 | 批量整理 | 复用已验证的单封操作、结果反馈与撤销能力 |

误操作保护分成 阶段 1 的确认和 阶段 6 的撤销，是因为移动后邮件 UID 会改变，不能用旧 UID 简单移回。七项需求逐项验收、独立提交，最后汇总成一个 PR。

## 3. 共用的最小约定

### 3.1 邮件身份与配置身份

- IMAP 邮件引用使用 `accountId + receiveEpoch + folder + uidValidity + uid`。`receiveEpoch` 隔离更换收信服务器后的身份空间；单靠 UID 或 Message-ID 都不够。
- 现有账户 ID 保持稳定；普通授权码、显示名、SMTP 更新不改变接收身份。收信端点或登录身份改变时生成新接收版本，隔离旧缓存、索引和检查点。
- 另用连接配置版本拒绝旧连接晚到的异步结果；不能用“换了密码”作为丢弃整个邮箱缓存的理由。
- 旧数据迁移到初始接收版本；无可靠代际的数据不得猜测绑定到新服务器邮件。导出目录只读保留，不被缓存清理删除。
- 新引用覆盖列表、搜索、阅读、附件来源、引用、已读/星标/移动/删除；POP3 保留协议适配，不能把进程内序号当跨启动身份。

### 3.2 操作结果

- 结果至少区分：进行中、确认成功、确认失败、部分完成、结果待确认；按账户/文件夹/邮件返回已知结果和可执行的恢复动作。
- `operationId` 用于本地防重与关联结果，不代表服务器支持幂等。
- 普通成功可轻提示后消失；失败和待确认在原页面保留入口。需要跨重启恢复的发送、移动记录持久化；不为每个简单提示引入独立任务中心。
- 网络超时不等于未执行。先核验服务器状态；仅重试确定未执行的部分。无法核实的项不计入成功数量。
- 按邮件维护操作版本，旧请求的失败不得覆盖用户更晚的操作。

## 4. 七项功能的实施与验收

### A. 误操作保护

**用户体验**

1. 普通删除仍移到废纸篓；废纸篓内彻底删除必须确认，展示邮件数量、单封主题及“无法撤销”。取消后不发送任何删除命令。
2. 工具栏、右键菜单、键盘快捷键共用同一个保护入口。连续按键不能弹出多个确认或重复提交。
3. 已确认完成且具备可靠身份映射的归档、移动、普通删除，显示带对象的“已归档 · 撤销”，建议提供 10 秒入口。
4. 撤销期间显示执行状态；失败或对象已被其他客户端移动时说明原因。永久删除不提供撤销。
5. 服务器不提供可靠映射时不宣称可撤销。开发时先验证目标邮箱支持情况，再决定是否另做“提交前短暂取消”；后者不能提前提示已完成。

**实现落点**

- 前端 `ui/app.js` 的删除入口、`moveCurrent` 和操作提示；结果逻辑抽到可测的小模块。
- 后端 `lib.rs::move_messages`、`imap.rs::move_uids`、`download_protocol.rs`。当前库调用丢弃目标 UID，需保留 tagged/untagged `COPYUID`，记录源/目标代际和 UID 映射。
- 撤销前重新校验目标身份；移回源文件夹后获取新的 UID，不复活旧列表对象。
- `COPY → STORE → EXPUNGE` 分阶段核验。复制成功但源未删除时显示待确认，不再次复制；批量命令返回 NO 也不能假定一封都没执行。

**TDD / 验收**：取消确认零命令；鼠标/键盘覆盖一致；重复按键不重复执行；移动后 UID 改变仍撤销正确；无 COPYUID、部分成功、目标消失、UIDVALIDITY 改变均不误操作其他邮件。

### B. 成功与失败反馈准确

**用户体验**

1. “全部标为已读”按真实范围和确认结果报告，例如“成功 18 封，失败 2 封，待确认 1 封”；范围仅覆盖已加载项目时写清楚。
2. 单封星标、已读操作明确失败时恢复原状态；结果未知先核验，不直接当失败回滚。
3. 发送、移动、下载、读取目录出错时保留原因和恢复入口，不能用空列表替代读取失败，也不能仅靠几秒 toast。
4. 发送确认成功与“副本待同步”分开；账户“设置已保存”与“连接已恢复”分开。

**实现落点**：先修 `ui/app.js::setFlag/markAllRead/loadArchives/sendCompose` 等当前路径；Rust 接口从纯字符串错误逐步增加错误类别与已知结果，保留原始诊断供排查。共享展示组件保持轻量，不把所有错误都变成阻塞弹窗。

**TDD / 验收**：跨账户一成功一失败不报全成功；部分批次失败不清掉失败对象；旧失败响应不覆盖新星标；目录读取失败不显示“还没有”；确定失败/待确认的重试行为不同。

### C. 发出邮件后能查到记录

**用户体验**

1. 普通发送和定时发送共用发送记录：主题、收件人、时间、发送状态、副本保存状态。
2. 服务器确认接受后显示“已发送”；副本未同步时显示次级状态。该确认不等于对方已读或最终投递成功。
3. 无已发送文件夹或 POP3 账户仍有本地发送记录，可查看与导出。
4. 无法确认是否发出的邮件进入“需要确认”，提供查看原文、检查已发送记录；重新发送需明确选择，不自动重复发送。

**实现落点**

- 新增发送记录模块，使用现有本地数据库及独立原文文件，沿用受限文件权限。数据库迁移不能与通讯录的 `user_version` 管理冲突。
- 在 SMTP 前持久保存实际发送原文、固定 Message-ID、信封收件人和 `sendId`；落盘失败则不发送。
- 状态区分 `prepared/submitting/accepted/rejected/unknown`，副本状态另列 `pending/saved/failed`。原文和数据库提交有明确顺序及崩溃恢复规则。
- SMTP 确认后先持久记账，再清理草稿和待发入口；复用 `save_to_sent/ensure_saved` 补存，失败重启可恢复，绝不因此重发 SMTP。
- “服务器接受”和“本地记账”之间无法原子提交；崩溃遗留 submitting 一律待确认。相同 Message-ID 不保证邮件服务器去重，已发送目录查不到也不能证明未发送。
- 待补存及待确认原文不参与普通邮件缓存淘汰；副本确认后才能按明确的记录保留策略清理。副本和本地记录去重展示。

**TDD / 验收**：落盘失败零 SMTP 调用；双击发送只提交一次；SMTP 成功后断网/退出，重启可查原文并补存；最终答复丢失或确认后数据库失败进入待确认；补存失败/成功回执丢失不触发重发；定时发送同样覆盖。

### D. 搜索范围与结果可信

**用户体验**

1. 明确范围：当前文件夹、当前邮箱全部文件夹、全部邮箱；初始沿用当前范围，不突然扩大搜索。
2. 跨文件夹搜索默认排除垃圾邮件和已删除，提供可见开关；直接进入这些文件夹搜索时包含当前文件夹。未读、星标、附件、发件人、日期作为显式条件。
3. 分开展示覆盖程度、最后同步时间和是否有后续结果。“正在索引”“部分正文未建立索引”“账户连接失败”不能都表现成没有邮件。
4. 未覆盖完整正文时显示“当前已索引内容中未找到”，不承诺不存在该邮件。
5. 已缓存/已下载的长邮件正文后半段可被搜索。首版全文范围是邮件正文，不包含附件内容/OCR。

**实现落点**

- `ui/app.js::requestServerSearch`、`lib.rs::search_messages`、`search_index.rs`、`imap.rs::fetch_body_texts`；聚合页不再只搜索当前已加载数组。
- 索引覆盖级别拆成 `none/prefix/full/skipped`，另记失败、更新时间、代际。旧 `has_body` 只能迁移为前缀覆盖；超时跳过不能标成全文完成。
- 复用摘要先行和后台增量索引，优先读 `body_store`、`archive_source` 的匹配原文；网络补正文遵循明确预算，读信优先，可暂停和重试。大邮件/超预算项明确保留未覆盖状态。
- 增加 `hasMore/nextCursor`，固定排序包含日期和完整邮件身份；查询范围及索引版本纳入游标，索引变化提示刷新，避免翻页重复/漏项。
- 本地先出结果，服务器标记异步更新；禁止为了获取已读状态阻塞本地搜索。过期查询、配置版本或代际的结果不得覆盖新查询。
- 先复用 SQLite；性能基准若证明确有需要，再决定是否迁移全文检索方案。

**TDD / 验收**：多账户多文件夹范围准确；聚合搜索能覆盖未加载历史；关键词位于原始邮件 16 KB 之后也能在完整索引中找到；超过 2000 条有稳定分页；同时间邮件不重不漏；部分索引、单账户失败和跳过正文有准确提示；已有归档原文不重复联网下载。

### E. 完善离线阅读

**用户体验**

1. 断网并重启后，仍可浏览已保存的文件夹、摘要及完整正文，显示“离线 · 上次同步时间”。
2. 区分完整邮件已保存、仅有摘要、缓存已清理、外部归档不在线、文件损坏；没有本地正文时解释原因。
3. 首版离线服务器邮件只读：能阅读、打开已有附件、保存本地草稿；不隐式标记服务器已读、不补发回执，也不排队执行移动、删除、星标。
4. 本机阅读进度与服务器未读状态分开。联网并核实身份后恢复在线操作，不自动回放离线动作。

**实现落点**

- 持久保存文件夹快照、最后验证时间、接收版本和 UIDVALIDITY，来自既有索引的已确认信息。
- 离线引用精确指向旧快照。持久 UIDVALIDITY 不是本次会话已验证的服务器代际，不能直接灌入 `known_body_validity` 绕过验证。
- 复用内存→磁盘→外部归档读取顺序，提供显式本地只读入口；列表、正文、附件和引用都必须使用相同身份。
- 重连后发现服务器代际变化，隔离旧快照，任何旧写操作不可落到新代同 UID 邮件；更新中的旧回调也要失效。
- 保留缓存容量、单封大小和归档读取超时约束；离线阅读不承诺缓存永久保留。用户导出文件保持只读。
- 首版保障 IMAP。POP3 需先持久化 UIDL 身份映射再独立验收；不能复用当前进程内编号冒充跨启动离线能力。

**TDD / 验收**：冷启动断网可读先前已保存邮件与附件；本地读取路径零 SELECT/FETCH/STORE/回执发送，后台连接管理不阻塞本地结果；只有摘要和拔盘状态准确；缓存淘汰、损坏不会显示另一封信；旧代 A/新代 B 重用同 UID 不串信；未知代际不猜测；重连不会把离线阅读自动批量标已读。

### F. 批量整理邮件

**用户体验**

1. 复选框、⌘ 多选、Shift 连选；选中不打开、不标已读。轻量操作栏显示数量及已读/未读、星标、归档、移动、删除。普通行点击或 J/K 打开单封邮件前，清空并退出批量选择。
2. 全选明确为“选择当前已加载的 N 封”；不自动选择未加载、后来搜索到或新收到的邮件。
3. 会话模式显示“X 个会话 / Y 封邮件”，只选本次列表内该会话的成员，不隐式扩展到另外加载的跨文件夹历史。成员变化不扩大选区，必要时半选。
4. 跨账户归档使用各自归档目录；移动到指定文件夹首版只支持同一账户。混合不支持项目先说明范围，不静默跳过。
5. 普通移到废纸篓与永久删除分开。混合包含废纸篓项目时默认不将它们夹带为永久删除；永久删除单独入口和确认。
6. 只清除确认成功项；失败/待确认保留选择和处理入口。变更账户、文件夹、搜索词、筛选或会话模式时清空批量选择。

**实现落点**

- 新建可测选择模块；`S.sel` 仍表示正在阅读的单封，批量选择独立存储并使用完整邮件引用。
- 按 accountId/接收版本/文件夹/代际分组，开始操作时冻结参数和目标，后端校验身份；同账户串行，不同账户有限并发。
- 复用 阶段 1 结果契约及 阶段 6 撤销能力；不重放成功组，未知组先核验。
- 输入框、写信、搜索、overlay 和 IME 不抢键。复选框上的 Space 切换勾选；批量 E/Delete 仅在列表选区或批量栏有焦点时执行。阅读区/正文有焦点时不得触发旧批量选区。J/K 退出批量后沿用单封导航；Esc 先关弹层再退出批量。

**TDD / 验收**：选中不触发已读；Shift 按当前排序；跨账户/会话真实目标准确；虚拟列表 200+ 行选择不依赖 DOM；筛选变化、刷新、新邮件不扩大选区；三账户含 POP3 的混合能力明确；部分失败不重复成功项；无焦点或输入中不执行批量快捷键；选 A/C 后通过普通点击或 J/K 打开 B，再按 Delete 只针对 B；阅读区/正文聚焦不触发旧批量选区。

### G. 账户故障可以原地修复

**用户体验**

1. 侧栏错误状态和设置中的账户卡提供“修复账户”；可更新授权码、检测收发信、重试连接，不要求移除重加。
2. 保留非敏感表单输入；新输入的授权码仅在当前表单临时保留以便重试，不写入日志或浏览器存储，关闭即清除。已有授权码不解密回传界面；留空表示保持原值。
3. 分开显示收信、发信检测结果。SMTP 检测只做连接/认证，不实际发送测试邮件。
4. 错误区分授权、网络/TLS、服务器配置和本地凭据存储；网络失败不默认要求更换密码。
5. 明确“保存失败，仍使用旧设置”“设置已保存，连接仍失败”“连接已恢复”。修改字段后旧检测结论失效。

**实现落点**

- `ui/app.js` 的账户表单/设置/同步状态；`lib.rs` 新增测试、更新连接配置、重连接口；复用 `config.rs` 与 `credentials.rs` 加密存储。
- 保留 account.id、签名、通知、规则、下载设置、草稿及待发记录，禁止借 remove_account/add_account 完成修复。
- 首版固定邮箱地址与接收协议；可以修改当前协议已支持的连接参数、SMTP 与授权码。OAuth、独立 SMTP 密码、账户协议转换另行规划。
- 配置与加密凭据跨存储保存须有可恢复提交记录或等效机制；落盘并回读确认后更新运行状态。崩溃后只能恢复一致的旧版或新版，不能混用新密码和旧服务器配置。
- 只重建目标账户连接，旧事件由配置版本隔离。仅授权码/SMTP 更新保留接收缓存；改变收信端点须推进 receiveEpoch，旧导出仍保留但不自动关联新服务器。
- 配置切换期间协调正在收发的任务；待发和草稿保留，旧附件来源校验，不能使正在发送的任务被重复启动。

**TDD / 验收**：添加失败自定义参数不丢；更新账户 ID/规则/草稿/待发不变；空白密码不覆盖；检测零发送且不保存；任一存储写失败/中断可恢复；旧连接迟到不覆盖新状态；改密码不清缓存；两台服务器恰好相同 UIDVALIDITY/UID 也不会串信；其他账户不断连。

## 5. 开发与验收方式

1. 每个阶段 先补能复现问题的失败用例，再实现最小范围，保留先红后绿记录。
2. 优先复用 Node 集成测试、`test_imap`、现有 SMTP/缓存/发送/迁移测试；故障注入覆盖请求前、部分执行后、确认后落盘前和重启恢复。
3. UI 用演示账户验证正常、空、失败、部分完成和待确认状态；截图展示布局，真实交互检查焦点、快捷键、滚动与窄窗口。
4. 每个阶段 由子 agent 独立审查，修复后复审。并行工作分支按依赖顺序汇总到同一个功能分支，最后只开一个 PR。
5. 发布前用专用测试邮箱验收真实 IMAP MOVE/COPYUID、服务器是否自动保存已发送、多账户部分故障、断网重启和重连。测试绿色、CI 绿色不替代这些验收。
6. 数据结构变更做旧版升级、写盘失败与崩溃恢复测试；同步更新使用说明中的能力边界。
