# 大邮件下载诊断与修复（2026-11-01）

## 实测结论

对用户授权的北航 IMAP 邮箱使用独立 Python SSL/IMAP 客户端测试，只执行 EXAMINE、SEARCH 和 BODY.PEEK；不修改服务器邮件状态。凭据仅在进程内读取，诊断输出不含密码、邮箱地址、正文或附件。

- 目标原文 29,854,016 字节，其中 HTML 正文编码后只有 9,952 字节，一个 PNG 部分为 29,194,778 字节。
- 同一连接的三个 512 KiB 样本分别为 36.44、39.68、43.95 KiB/s；整封流前约 1 MiB 为 39.84 KiB/s。慢速可以在应用之外复现。
- 与应用相同的正文分部请求为 0.352 秒，三个 literal 共 11,699 字节。第二次小分段测速变快，不能认定恒定服务器限速。
- TCP 乱序和重复接收计数增长；没有服务器侧或另一网络的对照，不能把问题进一步归因到服务端、账号共享带宽或某段网络。
- 服务器和本地摘要均为 791 封、未读 19 封；测试前本地完整原文有 715 封、缺 76 封。这里比较的是计数，未逐项比对服务器 UID 集合。搜索索引的 `has_body`/`body_coverage` 不等于原文已完整下载。

原版本将整封下载限制为 60 秒总耗时。上述 39.84 KiB/s 若保持不变，目标邮件约需 12.2 分钟（推算，非整封实测）。持续有数据也会被超时中断，失败后没有续传记录；已有临时正文又被整页错误覆盖。

## 最终行为

- 完整缓存仍优先。超过 5 MiB 且可以独立提取正文的邮件，先显示正文，用户点击“下载图片和附件”后才下载完整原文。常见小邮件仍自动完整加载。
- 此按钮下载图片和附件的整个集合，不是独立下载某个附件。现有附件序号、转发、导出与完整原文缓存保持一致。
- 临时正文保留 `partial` 身份，不作为完整离线缓存、不确认全文索引、不发回执；依赖完整原文的回复和转发待完整下载后启用。
- 完整下载失败时保留已显示正文与重试入口，原始错误不再被“本机只有摘要”覆盖。
- 下载连接连续 60 秒无新字节才超时。独立 IDLE 监听不启用该计时器。切换到另一封邮件会中断旧下载并丢弃旧连接，已确认分段仍保留。
- 分段从 64 KiB 开始，快连接逐步增大到最多 1 MiB，慢连接减小。每个分段收到匹配的 tagged OK，并校验 UID、offset、大小与长度后才提交。
- 续传数据使用独立私有目录，数据先落盘，再原子提交已确认长度。崩溃留下的未确认尾部不参与恢复。每个接收身份最多 3 项、128 MiB；单封超过该上限继续下载但不保留续传数据。
- 接收身份、文件夹代际和邮件 UID 隔离续传记录；完整缓存发布成功后才删除检查点。服务器拒绝分段时，仅在起点尝试一次完整读取回退。

## 验证

本次真实测试成功：正文优先耗时 0.894 秒；保存首个 65,536 字节分段后主动断开，新连接确认从 65,536 字节续传；续传阶段 658.467 秒后收到全部 29,854,016 字节。完整 MIME 解析得到正文和 1 个附件，磁盘原文与下载结果逐字节一致。测试后目标仍未读，收件箱仍为 791 封/未读 19；完整原文缓存增至 716 封，剩余 75 封未完整缓存。

自动验证：全套后端回归 633 项通过、14 项默认忽略；最后的协议兼容性测试 9/9、续传存储测试 8/8 均通过。前端回归 1006 项通过、10 项平台条件跳过。macOS 本机 release 构建及签名验证通过。

前端回归覆盖正文保留、身份变更、离线完整缓存、显式下载、重试与 iframe 保留；模拟浏览器界面确认按钮、失败提示、重试后附件和回复入口。滚动位置的真实视觉检查未得出结论，逻辑回归覆盖保留既有正文节点。

后端回归覆盖正文延迟返回、小邮件自动下载、强制完整下载、UIDVALIDITY 变化、未确认或错误分段、断线恢复、服务器不支持分段、持续传输超过固定时限、无数据超时、IDLE 不受影响、换信取消、半写恢复、存储上限、账户删除及完整缓存写入失败。

真实只读诊断默认忽略，且必须显式提供非秘密的目标参数。密码始终从当前本地凭据库读取，不接受密码环境变量：

```sh
MAILBEACON_LIVE_DOWNLOAD=1 \
MAILBEACON_LIVE_HOST='<已配置的 IMAP 主机>' \
MAILBEACON_LIVE_UID='<目标 UID>' \
MAILBEACON_LIVE_SIZE='<完整原文字节数>' \
cargo test -p mailbeacon-app --lib \
  download_live_tests::live_imap_large_mail_text_and_resumable_download \
  -- --ignored --exact --nocapture
```

该诊断仅执行 EXAMINE/BODY.PEEK；先验证正文，再保存首个确认分段并主动断开，重新登录后从检查点下载至完整，解析 MIME 并核对正常缓存发布。它会把成功下载的邮件写入本机正常缓存，不修改服务器标记。目标已经完整缓存时只验证现有缓存，不删除用户数据或强制重下。
